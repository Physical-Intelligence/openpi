# 动作空间与数据格式

本文是 UR5 双轴腕实验的中文项目文档，不是 Physical Intelligence 官方 OpenPI 原文。

## 9 维 state

```text
[UR5 实际关节角 6, 双轴腕 J1/J2 实际舵机相对 raw 2, 夹爪实际位置 1]
```

| 维度 | 含义 | 单位 |
|---:|---|---|
| 0–5 | UR5 六个实际关节角 | rad |
| 6 | `GET_WRIST_STATE.j1_pos - servo_zero_raw[0]` | raw |
| 7 | `GET_WRIST_STATE.j2_pos - servo_zero_raw[1]` | raw |
| 8 | 夹爪实际位置 | 归一化 `[0,1]` |

## 9 维 action

普通 SpaceMouse 控制最终调用 UR RTDE `speedL`，所以 action 保持笛卡尔速度语义，不改写成关节目标：

| 维度 | 含义 | 单位/坐标系 | 类型 | 运行范围 |
|---:|---|---|---|---|
| 0 | TCP `vx` | m/s，UR base | 瞬时速度 | 遥操作 ±0.107，硬上限范数 0.25 |
| 1 | TCP `vy` | m/s，UR base | 瞬时速度 | 同上 |
| 2 | TCP `vz` | m/s，UR base | 瞬时速度 | 同上 |
| 3 | TCP `wx` | rad/s，UR base 右手系 | 瞬时速度 | 遥操作 ±0.54，硬上限范数 0.60 |
| 4 | TCP `wy` | rad/s，UR base 右手系 | 瞬时速度 | 同上 |
| 5 | TCP `wz` | rad/s，UR base 右手系 | 瞬时速度 | 同上 |
| 6 | J1 目标相对 YAML 零位 | raw | 相对坐标中的绝对位置 | YAML 候选 `[-497,+290]` |
| 7 | J2 目标相对 YAML 零位 | raw | 相对坐标中的绝对位置 | YAML 候选 `[-725,+786]` |
| 8 | 夹爪目标 | normalized | 绝对位置 | `[0,1]` |

线速度和角速度上限是各自三维向量的范数上限，不是三个分量可以同时取最大值。

腕 action 不是相邻帧 delta。比如 action 第 6、7 维为 `[20,-10]`，当前
`servo_zero_raw=[3278,2547]`，驱动会向 OpenRB 发送绝对舵机目标 `[3298,2537]`。
更换装配并重新标定零位后，旧 episode 的相对坐标保持不变；推理只加上新的 YAML 零位。

AS5048A 的 `enc0_deg/enc1_deg` 和绝对电机 raw 可写入健康诊断，但不进入 9 维 state/action。

## 为什么不保存 SpaceMouse 原始值

训练 action 必须是经过映射、模式选择、限速、安全边界和设备控制语义之后的最终命令：

```text
SpaceMouse raw
→ 归一化/deadzone/轴映射
→ 平移、Shift 旋转或 Ctrl 腕模式
→ 速度与工作空间安全检查
→ UR speedL + J1/J2 相对 YAML 零位的目标 + 夹爪绝对目标
→ 完成控制周期的 command receipt
→ HDF5 action[0:9]
```

原始轴只能作为诊断 telemetry，不能作为训练 action。

HOME 和按键 1/2 使用 `speedJ`，语义不同。录制任务窗口中一旦出现非零 joint jog，整个 episode
必须拒收，不能把零 TCP action 错当成机器人没有运动。

## 最终 action 一致性门禁

历史控制路径存在三个容易污染训练标签的细节：

1. 输入状态和命令字段曾分两次发布，Recorder 可能混到相邻 125 Hz 周期。
2. UR worker 可能在上层构造 twist 后再次执行 TCP floor guard。
3. RTDE/RPC ack 没有回传 worker 保护后的最终 twist。

当前本地 `local_hardware.py` 和 `teleop_hardware.py` 采取保守策略：

- 完整控制周期结束后才发布不可变 command receipt；
- UR 维度使用 `UR5Controller.send()` 经过安全限幅后的实际返回值；
- 腕维度使用 `WristMasterSlaveController.step()` 实际下发的 J1/J2 相对 raw target；
- 夹爪维度使用驱动缓存中已下发的归一化绝对目标；
- episode 活动时禁止 HOME/J6 `speedJ`，维护动作期间不发布可录制的 9 维 receipt；
- 任一速度、数值、state、时间戳或同步门禁失败都拒收；
- Fit 上升沿先封存，再执行 reset/Home。

因此软件合同能保持统一 `speedL + 腕相对零位坐标中的绝对目标 + 夹爪绝对目标` 语义。
`teleop_session.py` 的独立 recorder 线程已接入 `teleop_hardware.py` 的
`observation["action_receipt"].action`，不会把 SpaceMouse 原始轴或上层候选值当成标签，
并有 Fake 会话测试。但尚未生成真机 HDF5，所以不能声称已在真机上验证
请求值、驱动返回值和机器人实际运动的一致性。

## 原始 HDF5

成功 episode 至少包含：

```text
/observations/qpos             float32 [N,9]
/action                        float32 [N,9]
/observations/images/front     uint8 [N,H,W,3]
/observations/images/side      uint8 [N,H,W,3]
/observations/images/top       uint8 [N,H,W,3]
/timestamps/control            int64 [N]
/timestamps/front              int64 [N]
/timestamps/side               int64 [N]
/timestamps/top                int64 [N]
/timestamps_host/front         int64 [N]
/timestamps_host/side          int64 [N]
/timestamps_host/top           int64 [N]
```

- `timestamps/control`：当前进程的单调时钟纳秒。
- `timestamps/{camera}`：RealSense 原始设备时间戳。
- `timestamps_host/{camera}`：收到相机帧时的 `time.monotonic_ns()`。
- 跨相机 skew 只能比较 host 时间轴，不能假定三台设备 raw clock 相同。

文件生命周期：

```text
episode_XXXX.tmp.hdf5
→ 正常 flush/fsync
→ episode_XXXX.hdf5

异常、丢弃、超时或安全失败
→ rejected/episode_XXXX.hdf5
```

成功文件属性至少包括：

```text
task
fps
success
git_commit
camera_serials
gripper_backend
gripper_state_source
action_space
robot_config_hash
wrist_coordinate
wrist_servo_zero_raw
wrist_raw_limits
```

正式默认数采不依赖旧参考工程，应保存当前 OpenPI 项目 commit、lock hash、五份
YAML hash、相机 role/serial 映射和动作合同。如果未来为对比而显式启用隔离的历史 adapter，
还必须额外保存旧参考工程的 Git identity，不能与默认本地数据混为同一版本。

## LeRobot 字段

离线转换后字段固定为：

```text
observation.state
action
observation.images.front
observation.images.side
observation.images.top
task
```

三路图像进入 π0.5 时映射为：

```text
front → base_0_rgb
side  → left_wrist_0_rgb
top   → right_wrist_0_rgb
```

真实 9 维 state/action 由 OpenPI 补到 32 维；模型输出只截取前 9 维。policy transform
不把腕 raw 换算成角度。第 6、7 维保持相对 YAML 零位坐标中的绝对目标，第 8 维保持夹爪
绝对目标。推理硬件层在安全过滤后才把第 6、7 维加回当前 YAML 零位。
