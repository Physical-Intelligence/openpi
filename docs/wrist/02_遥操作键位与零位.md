# 遥操作键位与零位

本文是 UR5 双轴腕实验的中文项目文档，不是 Physical Intelligence 官方 OpenPI 原文。

所有可修改值的唯一来源是：

- `examples/ur5_twinwrist/config/teleop.yaml`
- `examples/ur5_twinwrist/config/poses.yaml`
- `examples/ur5_twinwrist/config/safety.yaml`
- `examples/ur5_twinwrist/config/hardware.yaml`

本文用于解释，运行时代码应读取 YAML，不应再把键位和 Home 数值散落在 Python 中。

## 双轴腕的默认操作链

正式遥操的默认腕控制源不是 SpaceMouse，而是操作者佩戴的 ESP32 主腕：

```text
ESP32 主腕绝对编码器
→ 以 resume 时的姿态为主腕相对零
→ Enc0 位移 × 10 raw/deg → J1 相对 raw
→ Enc1 位移 × 14 raw/deg → J2 相对 raw
→ One-Euro 滤波、速度/加速度/jerk、软限位和单步限幅
→ 加上 poses.yaml 的 J1/J2 servo_zero_raw
→ OpenRB 从腕舵机绝对 raw 目标
```

启动顺序必须分成两步：

1. `OpenRBWrist.connect()` 本身只读 `GET_LIMITS` 和 `GET_WRIST_STATE`，不会运动。
   `WristMasterSlaveController.connect(enable_motion=True)` 随后会让从腕直接回到 YAML 的
   `servo_zero_raw=[3278,2547]`。它是真实运动，不能当作只读连接。
2. Home 完成后系统仍处于 `parked`；必须显式调用 `resume_master()`，才会把
   当下主腕姿态设为相对零并开始主腕→从腕跟随。

这个“Home 后先停住，再显式 resume”是防跳变的安全语义，不应省略。
`TeleopHardwareWorker` 不是省略这一步，而是在同一 owner 线程中明确调用
`resume_master()` 后才对上层报告就绪。

## SpaceMouse 轴映射

设备原始顺序：

```text
[x, y, z, rx, ry, rz]
```

经过除以 500、裁剪到 `[-1,1]` 和 0.12 deadzone 后，UR 输出顺序为：

```text
[-z, x, y, -rz, rx, ry]
```

- 无修饰键：控制 UR base-frame TCP 平移，最大 0.107 m/s。
- 按住 Shift：控制 UR TCP 旋转，最大 0.54 rad/s，平移清零。
- 按住 Ctrl：暂时覆盖默认的 ESP32 主腕跟随，UR twist 清零；cap X → J2
  （负号），cap Y → J1（正号）。

Ctrl 的优先级高于主腕。底层 `WristMasterSlaveController.clear_spacemouse_velocity()`
单独使用时，只会把速度清零并保持最后绝对目标，不会突然跳回旧的主腕基线。
完整遥操路径还多一层安全衔接：`TeleopHardwareWorker` 检测到 Ctrl 从按下变为
松开时，先 clear 保持，紧接着调用 `resume_master()`，以松开时的主腕姿态重建相对零，
然后自动恢复 ESP32 主腕跟随。这样既不跳回旧基线，也不需要操作者额外按 T。
Shift 表示“旋转模式”，不是加速键。

当同时存在多个腕目标时，仲裁优先级是：

```text
推理 policy 的 J1/J2 相对 raw 位置目标 > Ctrl SpaceMouse 速度覆盖 > ESP32 主腕跟随
```

设备安装方向可能改变“物理推前”对应的符号。第一次真机前必须先运行只读 SpaceMouse echo，
逐轴确认，不允许看 YAML 猜方向。

## UR5 的“零位”

当前项目没有定义 UR5 机械零位。它定义的是 TASK2 的安全起始关节姿态：

- 姿态：`poses.yaml -> ur5.task_home_rad`。
- Home 速度/容差/稳定时间：`poses.yaml -> ur5.home_*`。
- 允许真实运动的关节软限位：`safety.yaml -> ur5.joint_min_rad/joint_max_rad`。

```text
[ 3.2977943420, -1.5669592063, -0.9337509314,
 -2.2119277159,  1.5755716562, -1.0345171134 ] rad
```

这个姿态只能叫 `task_home`。第一次使用必须由现场操作者在示教器低速模式确认，不能因为它写在
YAML 里就认为一定安全。

Home 的当前软件参数是 P 增益 `1.50`、最大 `0.50 rad/s`、关节误差不超过
`0.010 rad`，并连续稳定 `0.30 s`。
`poses.yaml` 还保留一个历史 `last_point_rad` 候选：

```text
[ 3.2988367081, -1.3855517546, -1.6734727065,
 -1.6501811186,  1.5775959492, -1.0311530272 ] rad
```

它不是首轮 TASK2 的推荐 Home，除非现场重新确认并明确选择，否则不要使用。

## 双轴腕的零位

双轴腕训练坐标的零位是 YAML 中固定的舵机示数，不再由 AS5048A 动态建立：

- J1/J2 零位和顺序：`poses.yaml -> wrist.servo_zero_raw/state_order`。
- ESP32 主腕端口、Enc0/Enc1 映射、符号、raw/deg 和滤波：`hardware.yaml -> wrist`。
- J1/J2 舵机 raw 软限位、每步上限和 Home 收敛条件：`safety.yaml -> wrist`。

```text
YAML servo_zero_raw = [3278, 2547]
实际 state[6:8] = [j1_pos - 3278, j2_pos - 2547]
policy/action[6:8] = [J1 target - 3278, J2 target - 2547]
下发绝对目标 = round(policy/action[6:8] + [3278, 2547])
```

当前主腕映射为：

```text
Enc0 正方向 → J1 raw 增大
Enc1 正方向 → J2 raw 增大
state/action 顺序 → [J1, J2]
```

YAML 候选绝对限位是 J1 `[2781,3568]`、J2 `[1822,3333]` raw；换成当前零位的
相对范围是 J1 `[-497,+290]`、J2 `[-725,+786]` raw。真机连接还会连续查询
`GET_LIMITS`，实际控制取 YAML 与固件限位的交集。

这里容易混淆三种不同“零”：

1. YAML 从腕舵机零：当前 J1=3278、J2=2547，是数据和推理唯一使用的从腕原点。
2. 固件报告的 `j1_zero/j2_zero`：只用于启动一致性检查，不能覆盖 YAML。
3. ESP32 主腕相对零：恢复跟随时把主腕当下姿态作为操作者输入起点；它不改变训练坐标。
4. AS5048A 的 Enc0/Enc1 绝对角：只保存到健康/诊断信息，不参与 state、action、Home 或控制。

训练 state/action 使用第 1 种坐标，顺序固定为 `[J1,J2]`。这里的 action 是“相对零位
坐标中的绝对位置目标”，不是相邻帧 delta，也不是原始 SpaceMouse 轴值。

## 当前本地主从腕实现的边界

当前本地实现已经迁入参考目录的 One-Euro 滤波、velocity/acceleration/jerk target
shaper、2 raw 发送 deadband、18 raw 单步上限、单串口 owner 和异常 fail-closed。
没有迁入 AS5048A 输出闭环和历史 soft-home PI 流程，因为本实验明确改为舵机位置示数链。
这些参数已经有 Fake 测试，但尚未做真机方向、零位重复性和低速小范围验收。

## 夹爪零位

夹爪没有机械 homing，统一使用归一化绝对位置：

- `0.0/1.0/home_value` 语义：`poses.yaml -> gripper`。
- Hiwonder/Feetech 选择、串口、servo ID、raw 端点和安全阈值：
  `hardware.yaml -> gripper`。
- 归一化范围、变化率和收敛参数：`safety.yaml -> gripper`。

```text
0.0 = 打开
1.0 = 闭合
```

幻尔当前 raw 端点为 `630/860`，飞特为 `100/3995`。修改连杆或舵机后必须重新标定。
`connect/close` 表示打开/关闭串口，不代表张开/闭合夹爪。
